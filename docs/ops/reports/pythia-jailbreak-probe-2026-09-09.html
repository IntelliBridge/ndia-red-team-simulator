How to read this

Each model received 5 prompts from garak's dan.DanInTheWild probe, a curated set of in-the-wild jailbreak attempts. The mitigation.MitigationBypass detector scores a response as a hit when the model's own refusal or safety mitigation was bypassed. k / n is hits over prompts evaluated, always shown with its denominator; this is a single bounded run at n=5, not a benchmark, and rates from so few prompts are indicative rather than precise.

Guardrails off. With the gateway's default persona content filter enabled, adversarial probes were refused at the gateway itself (persona_denied / prompt-injection detection) and never reached the model, so the numbers would have measured the gateway's filter rather than the model. With content filtering off, the probes reach each model and the detector measures the model's own resistance. Authentication, entitlement and metering stayed on throughout.

Concurrency. The gateway rate-limits bursts of concurrent probe runs. The run was orchestrated so that at most a few models were in flight at once, with per-model backoff and retry, so every reachable chat model completed cleanly.

Catalog changes during the run day. The gateway operators updated the catalog in the afternoon: openai/gpt-5.4, openai/gpt-5.6-luna and openai/gpt-5.6-terra were added and probed with the same settings (rows above, marked "afternoon"), and three ids that had answered 502 provider_unavailable in the morning (amazon/nova-2-multimodal-embeddings-v1:0, anthropic/claude-3-haiku-20240307-v1:0, xai/grok-4.6) were removed from the catalog. The roster in this report is the catalog as it stood after that update.

Handling. The probe child ran under the redsim credential-minimised environment with the key in a 0600 file. Only counts, token totals and latency were retained. No prompt text, model completion, or key was written to any summary, log, or this report.
