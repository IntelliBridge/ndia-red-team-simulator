# HTTP API reference (`/v1/*`)

This page lists every route `redsim.api.app:create_app()` mounts on `main`
(verified by enumerating the router objects on 2026-09-08 at `4320740`),
then the ML routes the product spec adds, marked as planned. The
FastAPI-generated OpenAPI document at `/docs` (non-prod) is the executable
contract for the mounted set. For header semantics see
[`docs/architecture/auth.md`](../architecture/auth.md), for the role matrix
the same page's "RBAC" section, and for the planned routes section 17 of the
[product spec](../superpowers/specs/2026-09-08-adversarial-ml-redteam-spec.md).

Every route below requires either an `Authorization: Bearer …` header
**or** a valid `redsim_api_session` cookie, except `/health` and `/metrics`,
which are unauthenticated. Cookie-authenticated mutations additionally
require the `X-Redsim-CSRF` header that matches the `redsim_csrf` cookie
(see [CSRF](../architecture/auth.md#csrf-double-submit-cookie)).

Routes are grouped by RBAC tier. Roles rank `viewer` < `scanner` <
`remediator` < `approver` < `admin`. `viewer` passes every membership (read)
gate and fails every gated action.

| Tier | Mounted sections |
|---|---|
| **Open** | [Health](#health), `/metrics` |
| **Authenticated / membership** | [Runs](#runs), [Findings](#findings), [Reports](#reports), [Projects](#projects), [Orgs](#orgs), [Scanners](#scanners), [Targets (list)](#targets), [Auth profiles (list)](#auth-profiles), [WebSocket](#websocket) |
| **Remediator+** | [Verify](#verify), [Runs cancel](#runs-cancel) |
| **Admin** | [Targets (write)](#targets), [Auth profiles (write)](#auth-profiles), [Audit verify](#audit), [Logs](#logs), [Project settings](#project-settings) |

Removed with the pentest domain and no longer mounted: `POST /v1/scans`
(unmounted at M0, answers 404), tickets, agents, fix, `tools/kali`,
`exports/vulnfixer`, GitHub webhooks. Nothing answers on those paths.

## Health

### `GET /health`

Liveness probe. Unauthenticated.

```json
{ "status": "ok", "env": "dev", "db_configured": false }
```

`db_configured` is `true` when `REDSIM_DB_URL` is set. `GET /metrics` is the
Prometheus scrape endpoint. `GET /v1/__settings` is a non-prod debug view of
the resolved API settings.

## Runs

### `GET /v1/runs?project=<id>&limit=<n>`

List runs across the caller's accessible projects, or one project when
`project` is given (membership checked). Newest first, `limit` default 50.

```json
{
  "runs": [
    {
      "id": "run-abc123",
      "project_id": "proj-a",
      "status": "succeeded",
      "scanner": "ml.campaign",
      "mode": "api",
      "created_at": "2026-09-08T12:00:00+00:00",
      "created_by": "user:alice@example.com"
    }
  ],
  "next_cursor": null,
  "count": 1
}
```

Campaign runs will carry `scanner = "ml.campaign"` (verify runs `ml.verify`,
ingest runs `ml.ingest`) once the ML routes land. No run of any kind can be
created on `main` today.

### `GET /v1/runs/{run_id}`

One run with summary. **RBAC: project membership.** The wire shape is
deliberately unchanged by the ML vertical, the campaign record is served by
the planned sibling route `/v1/runs/{run_id}/campaign`.

```json
{
  "run": { "id": "run-abc123", "…": "…" },
  "jobs": [ { "id": "job-…", "type": "attack.run", "status": "succeeded" } ],
  "findings_count": 12,
  "stages": [ { "name": "clean_eval", "mode": "live", "success": true } ]
}
```

## Findings

### `GET /v1/findings?run=<run>&severity=<sev>&limit=<n>`

List findings for a run (or across the caller's projects when `run` is
omitted). Severity filter is one of `critical|high|medium|low|info`.

```json
{
  "findings": [
    {
      "id": "f-uuid",
      "run_id": "run-abc123",
      "project_id": "proj-a",
      "severity": "high",
      "status": "open",
      "source_tool": "redsim.ml/pgd",
      "validation_state": "unverified",
      "dedup_key": "…",
      "schema_blob": { "id": "…", "title": "…", "description": "…" }
    }
  ],
  "count": 1
}
```

`schema_blob` will carry the ML block of spec section 5.7 once campaigns
produce findings.

### `GET /v1/findings/{finding_id}`

One finding. `{finding_id}` is the **UUID** (`Finding.id`). **RBAC: project
membership.**

## Verify

### `POST /v1/findings/{finding_id}/verify`

Enqueue `verify.replay` for the finding through
`services.verify.create_verify_job` (audit event before the `Run` and `Job`
rows, before Celery). **RBAC: `remediator+`** (`verify.replay`). The worker
mirrors the outcome onto `findings.validation_state`.

On `main` this is the restored pentest-era replay: there is no ML branch
yet, so a call against an ML finding cannot verify anything. The planned
extension accepts an optional body `{defense, params}` and runs the
verify-after-harden loop (see Planned routes).

Response (`200`): `{ "run_id": "…", "job_ids": ["…"], "status_url": "/v1/runs/…" }`.

## Runs cancel

### `POST /v1/runs/{run_id}/cancel`

Cancel an in-flight run. **RBAC: `remediator+`** (`run.cancel`). Best-effort
`celery.revoke` on every queued or running job, the worker re-checks on each
heartbeat. Emits a chained `run.cancel` event.

```json
{ "run_id": "run-abc123", "status": "cancelled", "jobs_cancelled": 2 }
```

## Reports

### `GET /v1/runs/{run_id}/report.{ext}`

Stream the run's rendered report. `{ext}` is one of `md | json | html`.
**RBAC: project membership on the run's project.**

HTML responses carry the strict security headers:

```
Content-Security-Policy: default-src 'none'; style-src 'self' 'unsafe-inline'; img-src data:; base-uri 'none'; frame-ancestors 'none'; form-action 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
X-Frame-Options: DENY
Content-Disposition: inline
```

JSON and Markdown carry nosniff plus
`Content-Disposition: attachment; filename="redsim-<run>-report.<ext>"`.

| Status | Meaning |
|---|---|
| 400 | unknown ext |
| 403 | caller has no membership on the run's project |
| 404 | run unknown or report not yet rendered |

## Scanners

### `GET /v1/scanners`

Names and capabilities of every adapter in the scanner registry.
**Authenticated.** The pentest built-ins were removed, and no attack adapter
is registered on `main`, so the roster is empty and clients render an
explicit "no adapter registered" state.

```json
{ "scanners": [], "count": 0 }
```

Once the campaign adapter from PR #8 registers, it appears here as
`ml-campaign` with capabilities `adversarial_ml` and `explainability`. The
attack catalog itself is served by the planned `GET /v1/attacks`.

## Projects

### `GET /v1/projects`

Projects the caller has membership on, with the caller's role per project.
System callers (workers) get the whole list with `role="system"`. Backs
`useRoles` in the web app.

```json
{
  "projects": [
    { "id": "proj-a", "slug": "proj-a", "name": "Production", "org_id": "org-1",
      "daily_llm_budget_cents": 50000, "role": "admin" }
  ]
}
```

### `GET /v1/projects/{slug}/membership`

Members of a project. **RBAC: any membership on that project.**

### `PUT /v1/projects/{slug}/settings` {#project-settings}

Update project settings. **RBAC: `admin` on the project.** Body is additive:

```jsonc
{ "daily_llm_budget_cents": 50000 }   // or null to clear
```

`daily_llm_budget_cents` must be a non-negative integer or null, otherwise
`400`. The cap applies to the Pythia-routed hardening narrative.

## Orgs

### `GET /v1/orgs/{org_id}/cost?days=<n>` {#orgs-cost}

Per-organization LLM cost breakdown. **RBAC: membership on any project in
the org.** `days` defaults to 30, range 1 to 366 (`400` outside). The budget
block is always the current UTC calendar month. Costs are in cents, and with
Pythia as the only transport every row is a Pythia call.

```json
{
  "org_id": "org-1", "days": 30, "total_cents": 1875, "call_count": 41,
  "by_day": { "2026-09-08": 1875 },
  "by_model": { "pythia/auto": 1875 },
  "by_task": { "ml.harden_narrative": 1875 },
  "budget": { "monthly_cap_cents": 50000, "month_spent_cents": 1875, "remaining_cents": 48125 }
}
```

The web **/cost** page renders this endpoint.

## Targets

### `GET /v1/targets?project=<id>`

List targets registered to a project. **RBAC: project membership.**

### `POST /v1/targets`

Register a generic target. **RBAC: `admin`** (`target.manage`).

```jsonc
{ "project_id": "proj-a", "kind": "url", "value": "http://staging.example.com" }
```

The ML kinds `ml_model_artifact` and `ml_model_endpoint` are specified to be
rejected here with `400 use_models_route` once `/v1/models` exists.

### `DELETE /v1/targets/{target_id}`

Remove a target. **RBAC: `admin` on the target's project.**

### `GET /v1/targets/{target_id}/verification` and `POST /v1/targets/{target_id}/verify` {#target-verification}

Both keep their 404, membership and `admin` gates and then return
**`501 Not Implemented`** with an explicit message. The DNS-TXT / GitHub-App
ownership engine was removed with the pentest domain, and a target's
`verified` flag is never set in this build.

## Auth profiles

Stored authentication material, Fernet-encrypted at rest and never returned
by any endpoint. Kept for the Phase B black-box endpoint connector, unused in
Phase A. Writes are gated on `auth_profile.manage` (admin) and emit chained
`auth_profile.create` / `auth_profile.delete` events.

### `GET /v1/auth-profiles?project=<id>`

List a project's profiles, non-secret fields only. **RBAC: project
membership.**

### `POST /v1/auth-profiles`

```jsonc
{
  "project_id": "proj-a",
  "name": "endpoint-bearer",
  "kind": "bearer",               // form | bearer | header | cookie
  "config": {},                   // non-secret fields, by kind
  "secret": "the-token"           // write-only, never echoed back
}
```

The chained `auth_profile.create` event is written before the row, and the
secret is encrypted before either happens, so a missing
`REDSIM_AUTH_PROFILES_KEY` fails closed. `201` on success, `409` on a
duplicate `(project_id, name)`.

### `DELETE /v1/auth-profiles/{profile_id}`

`204`, or `404` when unknown. **RBAC: `admin` on the profile's project.**

## Audit

### `GET /v1/audit/verify?project_id=<id>&run=<run>`

Walk one chain (`run:<run>` when `run` is given, otherwise
`project:<project_id>`, default project `default`) and confirm every hash
links. **RBAC: `admin`** (`audit.verify`). Emits a chained `audit.verify`
event of its own.

```json
{ "chain_id": "run:run-abc", "verified": true, "event_count": 42, "head_hash": "47b1a9…" }
```

On a broken chain the response carries `verified: false` and
`broken_at_seq: <n>`.

---

## Logs

### `GET /v1/logs?run=<run>&project=<id>&service=<name>&severity=<sev>&request_id=<id>&since=<iso>&cursor=<id>&limit=<n>`

Query the `application_logs` mirror written by `redsim-log-ingest`.
**RBAC: `admin` on `project` (default `"default"`).** Cursor pagination on
the row id, descending. Every query emits a `logs.queried` audit event.

---

## WebSocket

### `WS /v1/runs/{run_id}/events`

Subscribe to live stage events for a run (Redis pub/sub backed).
**RBAC: project membership.**

Auth sources, in order:

1. `Sec-WebSocket-Protocol: redsim.bearer.<token>` (the server echoes it back).
2. `Authorization: Bearer …` header.
3. `redsim_api_session` cookie.

Frames are `{ "type": "stage", "name": "<stage>", "mode": "live", "success": true, "detail": "…" }`
plus `{"type":"heartbeat"}` keep-alives. The ML worker will publish one
`stage` frame per entry of `STAGES` in `redsim/ml/schema.py`. Close code
`1008` covers origin not allowed, auth required, no membership, and run not
found.

They are listed so the UI and the OpenAPI document can show them honestly,
and so nobody documents them as working before they exist. Gates are the
`Action` members already present in `redsim/api/policy.py`.

Error envelope for the planned routes:
`{"detail": {"code": "<snake_case>", "message": "…", "phase"?: "B", "field"?: "…"}}`.
Every enqueue returns `202` with `{run_id, job_ids, status_url}`. Phase B
routes (endpoint connector, text and detection modalities, KernelSHAP for
black-box targets, `Idempotency-Key`, PDF export, garak through Pythia, the
interoperability routes of section 27) return `501 not_implemented` with
`phase: "B"` and are never stubbed with fake output.

## Cross-cutting headers

| Header | When set |
|---|---|
| `X-Redsim-Request-ID` | Echoed back on every response. Supply your own to control correlation. |
| `X-Redsim-CSRF` | Required on cookie-authenticated mutations (POST/PUT/PATCH/DELETE). |
| `Content-Security-Policy` | Set on report HTML responses (and the planned artifact route). Not set elsewhere. |
| `X-Content-Type-Options: nosniff` | Set on every report response. |

## Error envelope

FastAPI's default `{"detail": "..."}` shape applies to every mounted route.
`4xx` and `5xx` responses are always JSON.

- `401 { "detail": "authentication required" }`: no bearer and no cookie.
- `403 { "detail": "CSRF token missing or mismatched" }`.
- `403 { "detail": "role '<role>' cannot perform '<action>' on project <p>" }`: RBAC.
- `404 { "detail": "run not found" }`: `ensure_run_access`.
- `429`: rate limit (per-user or per-project token bucket,
  `REDSIM_RL_USER_PER_MIN`, `REDSIM_RL_PROJECT_PER_MIN`).
- `503`: `REDSIM_DB_URL` missing, or (planned) the Celery broker unreachable
  at enqueue.
