# HTTP API reference (`/v1/*`)

This page enumerates every HTTP route the API exposes. For the auth
header semantics see [`docs/architecture/auth.md`](../architecture/auth.md);
for the RBAC role matrix see the same doc's "RBAC" section.

Every route below requires either an `Authorization: Bearer …` header
**or** a valid `aegis_api_session` cookie — except `/health`, which
is unauthenticated. Cookie-authenticated mutations additionally
require the `X-Aegis-CSRF` header that matches the `aegis_csrf`
cookie (see [F14b](../architecture/auth.md#csrf-double-submit-cookie)).

Routes are grouped by RBAC tier:

| Tier              | Sections                                                       |
|-------------------|----------------------------------------------------------------|
| **Open**          | [Health](#health)                                              |
| **Authenticated** | [Runs](#runs) · [Findings](#findings) · [Reports](#reports) · [Exports](#exports) · [Projects](#projects) · [WebSocket](#websocket) |
| **Scanner+**      | [Scans](#scans)                                                |
| **Remediator+**   | [Fix](#fix) · [Verify](#verify) · [Runs cancel](#runs-cancel) · [Tools (`read`)](#tools) · [Agents (`run`)](#agents) |
| **Approver+**     | [Fix (`apply=true`)](#fix) · [Agents (`execute=true`)](#agents) · [Tools (`active`, `execute=true`)](#tools) |
| **Admin**         | [Targets](#targets) · [Audit verify](#audit) · [Logs](#logs) · [Project settings](#project-settings) |
| **External (HMAC)** | [GitHub webhooks](#github-webhooks)                           |

## Health

### `GET /health`

Liveness probe. Unauthenticated. Returns:

```json
{ "status": "ok" }
```

## Runs

### `GET /v1/runs?project=<id>&limit=<n>&cursor=<id>`

List runs. Optional filters: `project`, `status`, `scanner`. Cursor-
based pagination via the last run id.

```json
{
  "runs": [
    {
      "id": "run-abc123",
      "project_id": "proj-a",
      "status": "succeeded",
      "scanner": "strix",
      "mode": "api",
      "created_at": "2026-05-28T12:00:00+00:00",
      "created_by": "user:alice@example.com"
    }
  ],
  "next_cursor": "run-xyz789",
  "count": 1
}
```

### `GET /v1/runs/{run_id}`

One run with summary.

```json
{
  "run": { "id": "run-abc123", … },
  "jobs": [ { "id": "job-…", "type": "scan.start", "status": "succeeded" } ],
  "findings_count": 12,
  "stages": [ { "name": "scan.start", "mode": "live", "success": true } ]
}
```

## Findings

### `GET /v1/findings?run=<run>&severity=<sev>&limit=<n>`

List findings for a run (or across the caller's projects when `run`
omitted). Severity filter is one of `critical|high|medium|low|info`.

```json
{
  "findings": [
    {
      "id": "f-uuid",
      "run_id": "run-abc123",
      "project_id": "proj-a",
      "severity": "critical",
      "status": "open",
      "source_tool": "strix",
      "validation_state": "poc_passed",
      "dedup_key": "sqli:routes/login.js",
      "schema_blob": {
        "id": "vuln-0001",
        "title": "SQL Injection in Login Form",
        "description": "User-supplied email parameter …"
      }
    }
  ],
  "count": 1
}
```

### `GET /v1/findings/{finding_id}`

One finding. `{finding_id}` is the **UUID** (`Finding.id`), not the
scanner-side identifier.

### `GET /v1/findings/by-scanner-id?run=<run>&scanner_id=<id>`

Deprecated compat lookup for callers that still know the upstream
identifier. **Sunset after v0.5.**

## Scans

### `POST /v1/scans`

Enqueue a scan. **RBAC: `scanner+` on the target project.** Emits a
chained `scan.start` audit row **before** the Celery task is touched.

Body:

```jsonc
{
  "target": "http://localhost:3000",
  "project_id": "proj-a",            // defaults to "default"
  "scanner": "strix",                 // strix | trivy | semgrep | nuclei | zap | codeql | bandit | grype | checkov | trufflehog | sonarqube | syft | bumblebee | deepsec
  "instruction": "Focus on the /login endpoint.",   // optional, scanner-dependent
  "override_authorized": false        // bypasses target-allowlist check
}
```

Response (`200`):

```json
{
  "run_id": "run-abc123",
  "job_id": "job-456",
  "status_url": "/v1/runs/run-abc123"
}
```

Errors:

| Status | Meaning                                                                       |
|--------|-------------------------------------------------------------------------------|
| 400    | `target` missing                                                              |
| 403    | RBAC failure OR target not on allowlist (and `override_authorized=false`)     |
| 401    | Authentication required                                                       |

## Agents

### `POST /v1/agents/{agent_name}/run`

Enqueue a registered CAI agent. Admission-only, mirroring `POST /v1/scans`: a
chained audit row is emitted **before** the Run/Job rows and **before** Celery
is touched, so a crash mid-enqueue can never leave a row without a matching
chain event. The `agent_run` Celery task does the execution (re-authorize →
`dispatch(agent_name)`); no dispatch happens in the route.

`agent_name` is one of the 16 wired agents — e.g. `codeagent`,
`blueteam_agent`, `recon`, `bug_bounter`, `red_teamer`, `web_pentester`,
`dfir`, `retester`, `reporter`.

**The `execute` flag selects the RBAC action and whether the agent actually
runs**, per the [effect-class gate](../adr/0004-unified-effect-class-gate.md):

- **`execute=false` (default)** — `agent.run` action, **RBAC: `remediator+`**.
  A `read`-effect agent (recon, SAST, reporting) runs and returns its findings.
  An `active`-effect agent (exploitation, live hardening) is **not** run: the
  worker's `dispatch()` returns `status="pending_approval"` carrying a structured
  attack/hardening **plan** for review — nothing irreversible happens.
- **`execute=true`** — `agent.execute` action, **RBAC: `approver+`** (mirrors
  `apply=true` on fixes). The gated agent is actually invoked.

A `read`-effect agent ignores `execute` — it always just runs (the target
allowlist is its only gate). Effect is a per-agent property, **not** a function
of domain: an `android_sast` agent is offensive-by-domain but `read`-effect; a
`retester` re-fires exploits so it is `active`-effect.

Body:

```jsonc
{
  "prompt": "Exploit the SQLi on /login.",  // required
  "project_id": "proj-a",                    // defaults to "default"
  "execute": false,                          // true → actually run an active agent (approver+)
  "target": "http://localhost:3000",         // optional; allowlist-checked if present
  "finding_id": "fnd-123",                   // optional
  "repo_path": "/work/repo",                 // optional
  "override_authorized": false               // bypasses target-allowlist check
}
```

Response (`200`):

```json
{
  "run_id": "run-abc123",
  "job_id": "job-456",
  "status_url": "/v1/runs/run-abc123"
}
```

When an `active` agent is enqueued with `execute=false`, the run completes with
a `pending_approval` result whose payload is the proposed plan (no live agent
runs to produce it):

```json
{
  "status": "pending_approval",
  "plan": {
    "agent": "red_teamer",
    "domain": "offensive",
    "effect": "active",
    "target": "http://localhost:3000",
    "intent": "Exploit the SQLi on /login.",
    "gated": true,
    "required_role": "approver",
    "to_execute": "re-invoke with execute=true (requires the approver role)",
    "note": "Executing will run active exploitation / attack tooling against the target."
  }
}
```

Errors:

| Status | Meaning                                                                       |
|--------|-------------------------------------------------------------------------------|
| 400    | `prompt` missing                                                              |
| 403    | RBAC failure (`remediator+` for `run`; `approver+` for `execute=true`) OR target not on allowlist (and `override_authorized=false`) |
| 401    | Authentication required                                                       |

## Fix

### `POST /v1/findings/{finding_id}/fix`

Enqueue a remediation. **RBAC: `remediator+` for `apply=false`;
`approver+` when `apply=true`.**

Body:

```jsonc
{
  "strategy": "patch",       // patch | live | deps | agentic
  "apply": false,             // commit the change (approver+)
  "open_pr": false,           // let the engine open a PR (agentic only; implies apply)
  "repo": "/path/to/repo"     // worker-side filesystem path
}
```

All four strategies share **one** human-in-the-loop gate (the
[effect-class gate](../adr/0004-unified-effect-class-gate.md)) — `apply`
defaults `false`, so a fix always **proposes** first:

- **`patch`** — generate a unified diff for a code finding. `apply=false` →
  `pending_apply` (diff only); `apply=true` → rollback-safe local commit.
- **`live`** — blue-team live hardening of a running target. `apply=false`
  returns a hardening **plan** (`pending_approval`) and the blue-team agent is
  **never** invoked; `apply=true` runs the hardening.
- **`deps`** — dependency-bump patch; same gate as `patch`.
- **`agentic`** — drives the vendored vulnerability-fixer engine. `apply=false`
  → engine runs diff-only (`--no-push --no-pr`), returns `pending_apply`;
  `apply=true` → rollback-safe local commit; `apply=true, open_pr=true` →
  **the engine opens the human-reviewed PR itself** (the PR review *is* the
  gate). PR mode needs `GITHUB_TOKEN` in the worker environment (passed via the
  subprocess env, never argv); absent it the engine soft-degrades to a failed
  outcome.

Response (`200`):

```json
{ "job_id": "job-789", "run_id": "run-abc123" }
```

## Verify

### `POST /v1/findings/{finding_id}/verify`

Re-run the finding's PoC against the target. **RBAC:
`remediator+`.** The verify outcome (`verified` /
`still_vulnerable` / `inconclusive`) is mirrored onto
`findings.validation_state` by the worker (F11).

Response (`200`):

```json
{ "job_id": "job-…" }
```

## Runs cancel

### `POST /v1/runs/{run_id}/cancel`

Cancel an in-flight run. **RBAC: `remediator+`.** Best-effort
`celery.revoke` on every queued / running job; the worker re-checks
on each heartbeat. Emits a chained `run.cancel` event.

Response (`200`):

```json
{ "run_id": "run-abc123", "status": "cancelled", "jobs_cancelled": 2 }
```

## Tools

### `POST /v1/tools/kali/{tool}`

Invoke a Kali tool via mcp-kali. Per-tool forensic audit row emitted via the
canonical chain (digests + refs, not raw output — see
[`audit-chain.md`](../architecture/audit-chain.md)).

`{tool}` is one of `nmap | nikto | sqlmap | gobuster | dirb | hydra | john | wpscan | enum4linux | metasploit`. The generic `command` tool is
disabled by default and returns `403` for **every** role.

Each tool carries an [effect class](../adr/0004-unified-effect-class-gate.md);
an unlisted tool fails **safe** (treated as `active`):

- **`read` tools** (`nmap`, `nikto`, `gobuster`, `dirb`, `enum4linux`, `john`)
  — recon/enumeration. `tool.invoke` action, **RBAC: `remediator+`**. Run
  immediately.
- **`active` tools** (`sqlmap`, `hydra`, `metasploit`, `wpscan`) — attack /
  state-changing. Gated like an `active` agent: `execute=false` (default)
  returns `status="pending_approval"` and the tool is **not** run; `execute=true`
  runs it and requires **RBAC: `approver+`**.

Body:

```jsonc
{
  "params": { "target": "127.0.0.1", "scan_type": "-sV" },
  "execute": false   // active tools only: true → actually run (approver+)
}
```

Response (`200`) for a `read` tool, or an `active` tool with `execute=true`:

```json
{
  "success": true,
  "tool": "nmap",
  "return_code": 0,
  "stdout": "…",          // truncated for the response; full in blob store
  "stderr": ""
}
```

Response (`200`) for an `active` tool with `execute=false`:

```json
{
  "tool": "sqlmap",
  "status": "pending_approval",
  "effect": "active",
  "params": {},
  "message": "active tool: resubmit with execute=true (requires the approver role)"
}
```

## Reports

### `GET /v1/runs/{run_id}/report.{ext}`

Stream the run's report. `{ext}` is one of `md | json | html`.

**RBAC: project membership on the run's project.** (Read tier — any
role is sufficient.)

HTML responses carry the strict v0.4.0 F14d security headers:

```
Content-Security-Policy: default-src 'none'; style-src 'self' 'unsafe-inline'; img-src data:; base-uri 'none'; frame-ancestors 'none'; form-action 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
X-Frame-Options: DENY
Content-Disposition: inline
```

JSON / Markdown carry nosniff + `Content-Disposition: attachment;
filename="aegis-<run>-report.<ext>"`.

Errors:

| Status | Meaning                                                                       |
|--------|-------------------------------------------------------------------------------|
| 400    | unknown ext                                                                   |
| 403    | caller has no membership on the run's project                                 |
| 404    | run unknown or report not yet rendered                                        |

## Projects

### `GET /v1/projects`

List projects the caller has membership on. System callers (workers)
get the whole list with `role="system"`.

```json
{
  "projects": [
    {
      "id": "proj-a",
      "slug": "proj-a",
      "name": "Production",
      "org_id": "org-1",
      "daily_llm_budget_cents": 50000,
      "role": "admin"
    }
  ]
}
```

### `GET /v1/projects/{slug}/membership`

Members of a project. **RBAC: any membership on that project.**

```json
{
  "project": { "id": "…", "slug": "…", "name": "…", "daily_llm_budget_cents": 50000 },
  "members": [
    { "sub": "dev:alice@x", "email": "alice@x", "display_name": "Alice", "role": "admin" }
  ]
}
```

### `PUT /v1/projects/{slug}/settings` {#project-settings}

Update project settings. **RBAC: `admin` on the project.**

Body (additive — pass only what you want to change):

```jsonc
{ "daily_llm_budget_cents": 50000 }   // or null to clear
```

Validation: `daily_llm_budget_cents` must be a non-negative integer
or null; anything else is `400`.

## Targets

### `GET /v1/targets?project=<id>`

List targets registered to a project. **RBAC: project membership.**

### `POST /v1/targets`

```jsonc
{
```

## Audit

### `GET /v1/audit/verify?all=1&run=<run>&project=<id>`

Walk one or more chains and confirm every hash links. **RBAC:
`admin`.** Emits a chained `audit.verify` event of its own.

Response:

```json
{
  "chains": [
    { "chain_id": "run:run-abc",  "verified": true, "event_count": 42,
      "head_hash": "47b1a9…" },
    { "chain_id": "project:proj-a", "verified": true, "event_count": 7,
      "head_hash": "fe2c01…" }
  ]
}
```

On a broken chain the response carries `verified: false` and
`broken_at_seq: <n>` so an operator knows where to look.

```json
      "attrs": { "scanner": "strix" }
    }
  ],
  "next_cursor": 482001,
  "count": 1
}
```

Every query emits a `logs.queried` audit event.

## WebSocket

### `WS /v1/runs/{run_id}/events`

Subscribe to live stage events for a run (Redis pub/sub backed).

Auth sources, in order:
1. `Sec-WebSocket-Protocol: aegis.bearer.<token>` (recommended for
   programmatic clients; the server echoes it back).
2. `Authorization: Bearer …` header.
3. `aegis_api_session` cookie.
4. (Legacy) `?token=<token>` query parameter — sunset in v0.5.

Frame shape:

```jsonc
{
  "type": "stage",
  "name": "scan.start",
  "mode": "live",
  "success": true,
  "detail": "strix returned 3 finding(s)"
}
```

Heartbeat frames (`{"type":"heartbeat"}`) keep the connection alive
when no real events are pending.

Close codes:

| Code | Reason                                                       |
|------|--------------------------------------------------------------|
| 1008 | origin not allowed / auth required / no project membership / run not found |

## GitHub webhooks

### `POST /v1/webhooks/github`

Receives `pull_request`, `push`, `installation` events from the
GitHub App. Verified by HMAC against `AEGIS_GITHUB_WEBHOOK_SECRET`;
deliveries deduplicated by `X-GitHub-Delivery` (10-min TTL set).

For `pull_request` events the response includes the structured PR
scope + restricted-mode decision (see
[`docs/security/fork-prs.md`](../security/fork-prs.md)):

```json
{
  "event": "pull_request",
  "delivery_id": "9bc8…",
  "action": "opened",
  "received": true,
  "scope": { "repo": "acme/widget", "pr_number": 99, "fork": true },
  "restricted_mode": "fork.restricted=true"
}
```

## Cross-cutting headers

| Header                | When set                                                                          |
|-----------------------|-----------------------------------------------------------------------------------|
| `X-Aegis-Request-ID`  | Echoed back on every response; supply your own to control correlation.            |
| `X-Aegis-CSRF`        | Required on cookie-authenticated mutations (POST/PUT/PATCH/DELETE).                |
| `Content-Security-Policy` | Set on report HTML responses (F14d). Not set elsewhere.                       |
| `X-Content-Type-Options: nosniff` | Set on every report / export response.                                |

## Error envelope

FastAPI's default `{"detail": "..."}` shape applies everywhere unless
otherwise stated. `4xx` and `5xx` responses are always JSON.

Common patterns:

- `401 { "detail": "authentication required" }` — no bearer + no cookie.
- `403 { "detail": "CSRF token missing or mismatched" }` — F14b.
- `403 { "detail": "role '<role>' cannot perform '<action>' on project <p>" }` — RBAC.
- `404 { "detail": "run not found" }` — `ensure_run_access`.
- `429` — rate limit (per-user or per-project token bucket).
