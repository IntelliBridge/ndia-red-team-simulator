# Bundled ML assets

This directory is populated by `redsim ml build-assets` (`redsim/cli/ml.py`,
orchestration in `redsim/ml/assets/build.py`). Everything in it except this
README is generated and gitignored: dataset caches, bundled weights and
evaluation slices are fetched or trained on the build machine and, in a
deployment, seeded into the blob store under `ml/assets/` and `bundled/`
(spec section 11.5 and 20.1 step 3). Nothing here is baked into an image.

```
redsim ml build-assets [--dataset image|tabular|cifar10|all] [--only MODEL_ID ...] [--epochs N]
                       [--out assets/] [--cache-dir DIR] [--seed N] [--image-size N]
                       [--max-train N] [--max-eval N] [--image-revision REV]
                       [--cifar10-revision REV] [--no-xgboost]
```

`--dataset` selects by dataset; `--only` selects by bundled model id
(`vehicles_cnn`, `cifar10_smallcnn`, `url_classifier`; repeatable) and
overrides `--dataset`. `--cache-dir` defaults to `$REDSIM_ML_DATASET_CACHE`
when that is set (spec 20.3, the cache the loaders share) and to `<out>/cache`
otherwise. The CLI entry points are P0's `add_ml_subparser`, `cmd_ml` and
`cmd_ml_build_assets`; `redsim.cli.ml.BUILD_ASSETS_STATUS` is `implemented`.

## Layout

```
assets/
  MANIFEST.json                       the record described below (only source of clean-accuracy numbers)
  bundled/<model_id>/weights.pt       SmallCNN state_dict (image models)
  bundled/<model_id>/model.joblib     URL classifier (or model.json when built with xgboost)
  bundled/<model_id>/surrogate.joblib PGD surrogate for the tabular model
  datasets/<dataset id>/<revision>/   bundled evaluation slices (npz for images, eval.csv for URLs)
  cache/                              raw downloads keyed by hub commit sha or Kaggle slug
```

Model ids: `vehicles_cnn` (image demo, `leibnitz-lab/military_vehicles`,
coarse 7-class task), `url_classifier` (tabular demo, Kaggle
`sid321axn/malicious-urls-dataset`), `cifar10_smallcnn` (CI fixture only,
`uoft-cs/cifar10`; `fixture_only: true`, never a demo target).

## Datasets and credentials

- HuggingFace datasets are resolved through the hub API to a commit sha and
  fetched from `resolve/<sha>/...` URLs with `httpx`; the sha is the recorded
  `revision`. CIFAR-10 comes from the `uoft-cs/cifar10` parquet files, not from
  torchvision's Toronto mirror (unreachable through the corporate proxy).
- The malicious-URLs file needs a Kaggle API token for the one-off build run
  only. `KAGGLE_API_TOKEN` (the variable the current Kaggle client reads) is
  sent as a bearer token; the older `KAGGLE_USERNAME` / `KAGGLE_KEY` pair is
  the basic-auth fallback. Each is read from the process environment first,
  then from the `.env` file `redsim.llm.pythia` discovers (`REDSIM_ENV_FILE`,
  else `./.env`, else the repo-root `.env`); the environment wins over the
  file. Kaggle answers the download endpoint with a 302 to a signed Google
  Cloud Storage URL, which the build follows with a second client that carries
  no `Authorization` header. The zip is hashed, `malicious_phish.csv` is
  extracted and hashed, and both digests plus the fetch time are written to
  `cache/kaggle--sid321axn--malicious-urls-dataset/download.json`; a re-run
  reuses the cached file only while it still hashes to the recorded value.
  Without credentials the build prints a clear message and trains on the
  committed CI sample `tests/ml/fixtures/malicious_urls_sample.csv`, marking
  the resulting dataset and model `fixture_only`. The secret is never logged
  or written anywhere: `KaggleAuth` hides it from `repr`, and log lines name
  only the variable and where it was read from.
- The committed sample is a seeded, stratified draw of 15 rows per class from
  the Kaggle file (`synthetic: false` in its sidecar
  `tests/ml/fixtures/MANIFEST.json`, which records the source file and archive
  digests, the 0-based source row indices, the eligibility rule and the seed).
  It is regenerated by hand after a tabular build has cached the file:
  `python -m redsim.ml.assets.fixture_sample --source assets/cache/kaggle--sid321axn--malicious-urls-dataset/malicious_phish.csv`.
  CI never contacts Kaggle.
- URL strings are data: the feature extractor is a pure string function and
  nothing in the build fetches, resolves or renders a URL. The `url` and
  `source_url` fields below are provenance strings for the same reason.
- Python TLS on the hackathon machines goes through an inspecting proxy; the
  build calls `truststore.inject_into_ssl()` when `truststore` is installed.

## MANIFEST.json

Schema: `redsim/ml/assets/manifest.py` (`AssetManifest`). Top level:
`schema_version`, `builder`, `built_at`, `redsim_version`, `python`, `platform`,
`library_versions`, `datasets`, `models`.

Each `datasets[<id>]` entry records `source` (huggingface, kaggle, local),
`revision` (hub commit sha, or the sha256 of `malicious_phish.csv`), `url`,
`license` and `license_note` as declared, `class_names`, the downloaded
`source_files` with sha256 and size (provenance; they live in the cache, not
under the root; for Kaggle both the zip and the extracted CSV),
`source_file_sha256` (the file the rows were read from), `archive_sha256`
(the Kaggle zip), `n_rows`, `splits` (name, `n`, per-class `n`, split seed,
sha256 of the source indices, the bundled slice file), `preprocessing`,
`n_duplicates_removed`, `fixture_only`, caveat `notes` and, for the committed
sample, `sampled_from` (the sidecar's source digests, row-index digest and
sampling rule).

Each `models[<id>]` entry is a `redsim.ml.schema.MLModelManifest` (the frozen
P0 contract that `targets.detail` stores and every loader reads) plus the
build record. `MLModelManifest.model_validate(entry)` holds for the JSON as
written; the build-only keys are ignored by that read.

The `MLModelManifest` fields and how the build fills them:

| Field | Value |
|---|---|
| `name` | human-readable model name (`redsim.ml.assets.MODEL_NAMES`) |
| `modality`, `format` | `image` / `torch_state_dict`, or `tabular` / `sklearn_joblib` (`xgboost_json` when built with xgboost) |
| `sha256`, `size_bytes` | the bundled model file's digest and size (same values as `file`) |
| `architecture_id` | `small_cnn`, `sklearn_hist_gradient_boosting` or `xgboost_classifier` |
| `input_shape` | `[3, H, W]` for the CNNs, `[16]` for the URL classifier |
| `n_classes`, `class_names` | from the dataset; lengths agree |
| `features` | URL classifier only: one `FeatureSpec` per lexical feature (`name`, `dtype`, `min`, `max` over the training split, `perturbable`) |
| `surrogate` | URL classifier only: `SurrogateInfo` (`kind`, `sha256` of `surrogate.joblib`, `agreement_clean` as an `AccuracyPoint` measured on the eval split: `n` rows, `n_correct` where the surrogate's label equals the ensemble's). `None` for the CNNs |
| `dataset_id`, `dataset_revision` | the dataset entry's id and revision |
| `dataset_split` | the split `clean_accuracy` was measured on (`test` for the hub datasets, `eval` for URLs) |
| `clean_accuracy` | `CleanAccuracy(value, n, split)`, measured at build time, never asserted |
| `status`, `refusal_reason` | `available`, `None` (a bundled model is loadable by construction) |
| `gradients` | `true` for the torch CNNs, `false` for the tree ensemble (PGD runs on the surrogate, spec 12.2) |
| `bundled` | `true` |
| `license`, `source_url` | the dataset's declared license and distribution page (a string, never fetched) |
| `manifest_sha256` | sha256 of the canonical JSON of the `MLModelManifest` projection (`sort_keys=True`, separators `(",", ":")`, `manifest_sha256` excluded), so a consumer holding only the projection recomputes it |

The build record adds `id`, `architecture` (constructor arguments), the
`file` (path under the root, sha256, size), `train_split`, `seed`, `epochs`,
the `training` recipe (optimizer, learning rate, batch size, thread count, wall
time, input mean and std, or the ensemble parameters and extractor version),
measured `metrics` (`n`, `n_correct`, `clean_accuracy`, `macro_f1`, per-class
`n` and `n_correct`, loss history), `extractor_version`, the surrogate's `file`,
`library_versions`, `fixture_only` and `notes`.

`redsim.ml.assets.manifest.verify_manifest(manifest, root)` re-hashes every
bundled file (weights, surrogates, evaluation slices) and recomputes every
`manifest_sha256`; a run refuses to start on any mismatch (spec 9.5, 11.3.3).
`verify_files` and `verify_entries` are the two halves.
